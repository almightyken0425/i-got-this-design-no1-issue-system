# F4 兩個方向比較

[index.html](index.html) 提供 A 工作台與 B 圖像分區。切換方向時保留同一筆工單與同一份暫存內容。參考圖頁有外殼、看板、詳情各兩張官方截圖，每張附一句借用重點與來源。

本輪保留第一批 F4 的 Design 與 Impl 修改，新增獨立比較稿。範圍仍是外殼、看板與工單詳情，等使用者選方向後再延伸其他畫面。

## 比較重點

| 面向 | A 工作台 | B 圖像分區 |
| --- | --- | --- |
| 外殼 | 固定側欄，圖示搭配短標籤。 | 頂部圖示導航，內容區較寬。 |
| 看板 | 緊湊直欄，便於跨階段掃讀。 | 橫向階段分區，圖示與工單標題較突出。 |
| 詳情 | 左側關聯與歷史，右側集中屬性。 | 大標題、橫排屬性與分區內容。 |
| 取捨 | 同屏容納量較高，導航文字較多。 | 圖像層級較明確，垂直捲動較多。 |

配色沿用已確認 F4 的白、冷灰與藍。兩個方向都沒有 checkbox、radio 或仿造選取框。外部參考截圖保留來源原貌，僅借用標示的版面特徵。

## 共用內容與操作

資料來自本機 I Got This 開發資料庫的唯讀查詢。取樣日為 2026-10-18。當時只有 IGT-1 工單A 與 IGT-2 工單B，檢視名稱是測試檢視。使用者已確認本輪先用這兩筆原始資料比較版型。這些名稱不足以證明是實際業務案例，因此本包稱為本機原始資料快照。

兩筆工單各在待處理與處理中。流程有待處理、處理中、審查中、已完成四個實際定義的狀態。保留七筆原始異動記錄，工單目前未填的欄位仍顯示未填寫。沒有補造描述、圖片、負責人、關聯或工時。內部識別碼改用預覽別名，操作者姓名改顯示原始操作者。

頁面載入第一批 F4 的實際前端元件快照，再套用兩組候選樣式。搜尋、工單進出、標題與欄位編輯、流程轉換和結案原因確認在獨立預覽中執行。資料只在記憶體保留，重設資料會回到原始快照。選擇未配置資料的操作會提示回到產品內完成。其他畫面的導航入口保留，這輪不展開其他畫面。

原始資料量不足以判斷大量工單與完整描述的閱讀密度。選方向前可用這份內容比較版型，後續應補入使用者指定的代表性工單。

## 來源與維護

- directions.css 持有兩個方向的候選布局，尚未改寫正式 Foundations。
- snapshot.js 持有共用內容與隔離的預覽介面。
- runtime.js 與 runtime.css 是第一批 F4 的前端快照。provenance.json 記錄來源版本與雜湊。
- compare.template.html 持有比較頁外框，references.json 與 assets 持有六張參考圖及來源。
- build.cjs 產出獨立 index.html，只需執行 `node build.cjs`。頁面不依賴外部字體、圖庫或服務。

比較稿沒有變更 Impl、Spec、資料庫或第一批 F4 檔案。比較稿與第一批 F4 修改由 feat/igotthis-f4-redesign 主題一同保存，A／B 方向仍待選定。Quality owner 與 Debug 影響沿用前次確認的 none。
